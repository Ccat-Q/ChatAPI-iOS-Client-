## 2026-10-23 应用锁设置与连接耗时补查

用户要求关闭 Face ID 的设置入口，并报告连接缓慢。源码确认三个可避免的等待来源：已验证前台会话仍可重复验证；工作台连接前再次串行请求 session；切换标签即断开并重连。还发现首次快照没有独立截止时间、每次获取 APIClient 都创建网络会话、重新选择当前实例会清空已验证状态。

修复将应用锁偏好持久化在本机（默认开启），关闭仅跳过启动和返回前台认证，敏感操作仍独立认证。工作台由标签容器持有，复用同一前台会话的 APIClient；恢复会话先验证，随后直接进行 Cookie WebSocket 握手。首次快照 15 秒超时，失败从 1 秒退避并提供立即重连，401/403 分别按失效和权限错误处理。旧客户端回调与旧连接超时不能修改新会话。

增加实际服务层回归验证请求次数、超时和错误状态，以及认证偏好与旧回调。所有编译仍由 Actions 执行；本轮结果记录于 PR 检查。尚无用户真实服务器的耗时采样，因此不宣称消除了服务器、代理或 DNS 的延迟；真机验证需同时覆盖关闭锁后的前后台切换与会话恢复。

## 限制与后续验收

这些属于现有功能边界或需真实环境验证，不宣称已在 CI 完成：

- 设备生物识别、应用切换器截图、真实 OIDC/验证码提供方和 Bark 投递，按 [真机验收](../development.md) 检查。
- Cookie 仍按系统域/路径共享，同主机不同端口的独立实例可能互相影响。建议独立主机名；若要彻底隔离，需要新的 Cookie 生命周期设计并复核 ADR 0002。
- 没有自动迁移旧的无实例草稿；无法可靠归属，避免把其他服务器输入带入当前会话。
- AI 工具建议已实现常用 schema 子集校验；完整 JSON Schema、媒体上传、内建工具、自动化录制和高级动作编辑尚未实现；见 [功能边界](../features-and-protocol.md)。
- REST 1 MiB 限制发生在下载结束后，不能限制下载过程全部磁盘/网络消耗。大规模请求列表后续应由服务器分页契约配合解决。

修复不自动合并到 main，也不发布带签名安装包。
