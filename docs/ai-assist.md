# AI 自动补全与消息编辑区

## 产品行为

消息回复、工具调用参数、工具结果均支持 AI 建议。辅助模型由用户单独配置兼容 API 的 Base URL、协议、模型和密钥；不把 ChatAPI 的人工响应接口当作辅助模型，避免循环创建人工任务。

用户可点击生成，也可在保存配置后启用自动建议。自动建议等待输入停顿后发起，最多保留一个正在生成的请求。返回结果作为独立预览展示，用户可采纳、放弃或重新生成。采纳后仍是普通可编辑草稿，不自动发送、不执行工具。发送后仍须收到匹配的 WebSocket 确认才清空输入。

修改草稿、工具字段、模式、最近会话上下文，或离开页面、进入后台时，取消旧请求并使旧建议失效。采纳建议本身不会立刻触发下一轮自动生成。

## 配置与数据范围

配置按实例 UUID 与已验证用户 ID 隔离，保存在本设备 Keychain；删除实例同时删除对应配置。此密钥属于用户辅助模型服务，不是 ChatAPI 登录凭据，不写进 UserDefaults、源码、日志或文档。

模型调用使用独立的临时 URLSession，禁用 Cookie、缓存和重定向，45 秒超时，响应流量读取上限 1 MiB。默认 HTTPS；开发 HTTP 需显式启用。不把当前实例的 Cookie 或应用密钥附带给模型服务。

发给模型的内容包括：当前操作模式、草稿、可选补全要求、工具名称/调用 ID、最近最多 12 条文本（每条最多 2000 字符），以及最近请求所声明的工具定义。图片、附件、服务器凭据和整个工作区不发送。完整编码输入也有大小限制，超过时提示缩小范围。

配置页说明数据将发送到用户填写的服务，并允许控制自动建议。未配置时仍可正常手动回复，AI 操作会提供配置入口。

## 协议与校验

支持 Chat Completions 与 Responses 两种兼容协议。Base URL 通常带 `/v1`；客户端追加对应 `chat/completions` 或 `responses` 路径。模型按约定返回 JSON 建议，客户端严格解析后展示。

工具定义来自时间线消息的 `metadata.request_debug.tool_schemas`。工具调用建议需要 JSON 对象参数；有 schema 时检查工具名称、基本类型、required、enum 和常用边界约束。复杂 JSON Schema（如远程引用、组合约束）仍由服务器最终验证，客户端不宣称完整实现 JSON Schema。关联工具结果时沿用操作者输入的调用 ID，不让模型任意改写请求关联关系。

## 认证页面与液态玻璃

锁定页使用普通全屏背景、固定的内容宽度、可滚动布局、验证进度、明确解锁按钮和可恢复错误提示。使用实际设备的 Face ID、Touch ID 或设备密码名称。每次前台会话最多自动尝试一次；用户取消后需手动重试，避免系统认证导致的 active/inactive 切换反复弹窗。

已锁定时短暂 inactive 不显示覆盖整页的隐私遮罩；后台始终遮挡，已解锁界面 inactive 时也遮挡。旧认证结果不能在重新锁定后放行。

消息正文为普通内容层。编辑区以安全区域底部的浮动玻璃面板承载模式选择、工具字段、文本输入和操作栏。使用系统 `GlassEffectContainer`、`glassEffect` 和玻璃按钮样式，并在降低透明度时使用不透明背景，支持大字体、键盘和 VoiceOver。

## 验证

所有编译和运行检查通过 GitHub Actions。新增认证取消/重复进入前台/锁后回调、辅助模型请求隔离、协议解析、响应上限、工具参数校验与取消回归。模拟器截图使用 Debug 专用的固定预览数据展示锁屏、消息和工具输入；Release 不包含预览路由。截图与回归不能替代真机 Face ID 和实际模型服务验收。
